퀴즈 16문항(정답 위치 ①5 ②5 ③6).

**선생님 운영 메모** — 01의 정의·비교 표·필요성 카드는 「훑기만」 하고 분류 게임으로 바로 넘어가요(질문폼 1번 근거는 분류 게임과 표). 탄소 중립 메모는 한 줄이면 충분하고, 시간이 밀리면 마무리 화면에서 써도 돼요. 02·03 체험까지 14~22분 안에 들어가야 04 프레임 체험이 30분 안에 끝나요. 질문폼(info-u2-compression) 1번 ← 01 분류 게임·필요성, 2번 ← 02·03 압축기(`rleHi`·`rleLo`·`cmpResult`·`cmpWhy`), 3번 ← 04 프레임 체험(`frameRes`·`mpegWhy`).

**성취도 평가 맞추기** — 교과서 성취도 평가 문장을 화면 끝 「✅ 성취도 평가」 칩으로 두고, 화면 흐름을 그 문장에 맞춤: 01 ← 52쪽(필요성 설명), 03 ← 53쪽(압축 기법 적용·효율성 분석 — 02 런 길이와 03 비교를 마친 뒤), 04 ← 56쪽(기본 원리를 간단한 데이터에 적용 — 프레임 계산), 05 ← 57쪽(품질·용량 분석, 방법 간 효율 평가 — 이미지 비교).

**50분 흐름** — 도입(3분) 단원 핵심 질문·이산화탄소 막대만 짚고 알고 있나요 칩, `planComp` → 01(5분) 정의·비교 표·필요성 카드 훑기, 분류 게임 5장(질문폼 1번 근거, 8분 무렵 끝), 탄소 중립 메모는 한 줄 → **02(8분 무렵 시작, 6분)** 압축기 미션 ①②·복원 → **03(14분 무렵 시작, 8분)** 교과서 예 확인 → 내 문자열 비교·기록(질문폼 2번 근거) → **04(22분 무렵 시작, 8분)** JPEG·MPEG·소리 카드 훑기, 프레임 체험·계산·메모(질문폼 3번 근거, 30분 무렵까지 마침) → 05(9분) 그림 두 가지 비교·확대·기록, 빈칸 → 마무리(6분) 처음 생각과 비교, 퀴즈, 질문폼. 코랩은 접어 두었고 시간이 남거나 다음 시간 시작에 씀.

**57쪽 코랩 실습을 접어 둔 까닭** — 이 차시는 단원 도입부터 57쪽까지 12쪽 분량이라, 코랩을 열고 로그인·사진 준비·셀 실행까지 하면 10분 이상 걸려 50분 안에 끝나지 않는다. 그래서 같은 성취도(품질·용량 분석, 방법 간 효율 평가)를 노트북 브라우저 안에서 바로 체험하게 하고(PNG 무손실 vs JPEG 손실, 그림 종류에 따라 결과가 달라짐), 교과서 그대로의 BMP·PNG·GIF 비교는 고친 노트북을 `assets/`에 넣어 「선택 또는 시간이 남을 때」로 두었다. 브라우저는 GIF로 저장하는 기능이 없어 체험에서는 GIF 대신 JPEG를 썼다(GIF는 펼친 화면에 한 줄, 접은 코랩 부분에 자세히).

**고친 노트북(`assets/image_compression.ipynb`)** — 원본(`작업자료/교과서코드_2단원/고정보_57쪽_이미지_압축.ipynb`)에서 고친 점:
- `print('JPG 이미지 해상도, im.size')` → 따옴표 위치 오류로 크기가 아니라 글자 「im.size」가 그대로 찍힘 → `print('이미지 해상도', im.size)`
- `print('GIF 이미지 해상도', 'im3.size')` → 변수에 따옴표가 붙어 글자가 찍힘 → `print('이미지 해상도', im3.size)`
- 원본 노트북은 JPG를 원본으로 쓰는데 교과서 57쪽은 BMP를 원본으로 씀 → 교과서대로 BMP를 원본으로 만들어 BMP·PNG·GIF를 비교(JPG는 이미 손실 압축된 파일이라 원본으로 알맞지 않음)
- 교과서 57쪽 코드 `Image.open('flower_BMP.bmp')` 다음 줄이 `getsize('flower_bmp.bmp')`로 대소문자가 달라 코랩(리눅스)에서는 파일을 못 찾는 오류가 남 → 파일 이름을 `my_BMP.bmp` 하나로 통일
- 교과서용 꽃 사진은 넣지 않음. 학생이 고른 사진을 올리거나(선택 셀), 올리지 않으면 코드로 꽃잎 그림을 그려 씀. 사진 셀에 「얼굴·개인 정보가 드러난 사진은 쓰지 않기」 안내
- 압축률 계산 셀, 가운데를 확대해 세 형식을 나란히 보는 셀, (더 해 보기) JPEG 품질별 비교 셀을 덧붙임. `show()` 대신 `display()` 사용
- 로컬에서 업로드 셀을 뺀 나머지를 실행해 확인함(코드 그림 480×320: BMP 460,854 / PNG 159,507 / GIF 94,122 Bytes)

**줄인 것** — 48~49쪽 만화와 핵심 역량 목록은 넣지 않음(K-Culture는 두 문장, 알고 있나요는 칩으로). 50쪽 데이터 센터 사진·만화는 이산화탄소 막대로만. 52쪽 함께 해결하기 1번(친환경 데이터 센터 사례 찾기)은 「시간이 남을 때」로, 2번만 메모. 52쪽 부록 링크(241쪽)는 넣지 않음. 54쪽 지식 키우기는 체험의 기본값(교과서 예)과 트리 그림으로 대신함. 55쪽 사진 예시(색 변화·밝기 변화)는 카드 글로만, 56쪽 소리 그래프는 표본화·양자화·부호화 세 칸 설명으로 바꿈. 53쪽·56쪽 스스로 해결하기는 교과서 문자열·사진 대신 새 문자열·새 프레임 그림으로 바꿈(공개 저장소에 교과서 답이 드러나지 않게). 개념 정리하기는 교과서 문장을 옮기지 않고 새 상황 문장 빈칸으로.

**선생님 준비물** — 따로 내려받을 데이터 파일 없음. 코랩(선택)을 쓰면 학교 구글 계정 로그인만 필요. 교과서 57쪽의 꽃 BMP 사진을 쓰고 싶으면 드라이브 폴더(교과서 소스 코드 2단원 57쪽)에서 학생에게 나눠 주고, 노트북의 「사진 올리기」 셀로 올리면 됨(저장소에는 넣지 않음).

**확인할 점**
- 51쪽 그림 Ⅱ-1 말풍선과 표의 「무손실 압축은 원본과 **거의** 같게 복원」 — 53쪽 본문은 「원본과 **똑같이** 적는 것이 무손실 압축의 원리」라서 서로 어긋남. 무손실은 원본과 같게 복원되므로 화면에는 「원본 그대로 복원」「원본과 같게 복원」으로 씀.
- 51쪽 표에서 GIF를 무손실 압축 형식으로 분류하지만, 57쪽은 「256색만 표현 가능하여 그림의 품질은 낮다」고 함. 색이 많은 사진을 GIF로 바꾸면 256색으로 줄이는 단계에서 색 정보가 바뀜(압축 자체는 무손실). 화면·노트북에는 교과서 설명 그대로 두고 따로 풀어 쓰지 않음 — 수업 중 질문이 나오면 선생님 설명 필요.
- 53쪽 「런 길이 부호화를 사용한 대표적인 이미지 파일 형식으로 BMP」 vs 57쪽 BMP를 압축하지 않은 원본으로 씀. BMP는 런 길이 압축을 쓸 수도 있지만 보통은 압축하지 않고 저장함. 05 체험 화면에는 「여기서 만드는 BMP는 압축하지 않고 픽셀마다 색을 그대로 적은 파일」이라고 밝힘.
- 53쪽 스스로 해결하기 1번 표의 주어진 값은 계산이 맞음을 확인함. 반복 횟수가 두 자리면 두 글자로 셈 — 체험도 같은 방식.
- 54쪽 사전 압축은 문자 4종류에 001~100의 3비트 코드를 씀(2비트로도 충분하지만 교과서 방식대로). 체험은 「등장 순서대로 1부터 번호를 이진수로, 최소 3비트(문자 종류가 8가지 이상이면 4비트)」로 일반화함. 64쪽 맞춤 활동(5종류, 001~101)과도 맞음. 사전 자체의 크기는 교과서처럼 계산에서 뺌(화면에 밝힘).
- 54쪽 허프만 부호화: 옆 설명 3단계 「값이 같다면 정렬 순서가 앞인 것에 0」과 트리 그림을 비교하면, 묶은 노드는 같은 값의 기존 문자보다 **뒤**에 정렬됨(A:3과 묶음 3 → A가 0). 체험은 이 규칙(빈도 내림차순, 같으면 먼저 나온 것이 앞, 새 묶음은 같은 값 중 맨 뒤)으로 구현해 교과서 코드(O=1, A=00, D=010, B=011, 19bits)와 같게 나옴. 「지식 키우기 ➋」의 「등장하는 순서대로 왼쪽 또는 오른쪽」 설명은 옆 설명과 표현이 다름.
- 54쪽 지식 키우기 ➍ 결과 「0000000100 100111111」은 띄어쓰기 위치만 어색하고 비트열은 맞음(00 00 00 010 010 011 1 1 1 1).
- 56쪽 스스로 해결하기의 사진 프레임은 쓰지 않고 새로 그린 격자 프레임으로 바꿈. 교과서처럼 두 번째·세 번째 프레임 모두 첫 번째 프레임을 기준으로 달라진 격자를 셈.
