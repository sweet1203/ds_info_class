**질문폼(info-u3-data-1d) 근거** — 1번 ← 01 변수 여러 개 vs 리스트 하나(`whyMulti`), 2번 ← 02 코드 읽고 예측하기(`trList`·`idxWhy`), 3번 ← 03 리스트/딕셔너리 고르기(`pickWhy`)·03 코드 읽고 예측하기. 셋 다 27분 무렵까지 끝남. 코랩 실습은 질문폼 근거로 쓰지 않음.

**50분 흐름** — 도입(3분) 선미 이야기·처음 생각 → **01(3~10분)** 그림 Ⅲ-7·Ⅲ-8 훑기, 슬라이더 비교(1분), 메모, 차원 분류 6장 → **02(10~18분)** 리스트 설명·교과서 예제 결과 확인, 예측하기(2분), 메모 → **03(18~27분)** 딕셔너리 설명·예제 결과, 예측하기(2분), 리스트/딕셔너리 고르기 6장, 메모 → **04(27~43분)** 코랩 열기·로그인·사본 저장(3~4분), 예제 실행 → 신발 치수 리스트 → 하의 치수 딕셔너리 → 메모·개념 정리 → 마무리(43~50분). 더 해 보기는 먼저 끝낸 학생용.

**코랩 노트북(`assets/list_dict.ipynb`)** — 교과서코드 127·128쪽을 바탕으로 만듦. 출력은 비운 채 저장. 로컬 python3로 모든 칸을 실행해 확인함(스스로 해결하기 빈칸 칸은 시험할 때만 답을 넣어 실행, 4-2의 IndexError는 의도한 오류).
- 예제 따라 하기: 127·128쪽 본문 코드 그대로(127쪽 9번 줄 주석은 교과서 쪽 문장 「…출력하기」를 따름, 교과서코드 파일은 「…수정하기」).
- 127쪽 스스로 해결하기: 1번은 신발 치수 값을 학생이 정하게 함(교과서코드 파일·교사용 교과서의 예시 값은 넣지 않음). 2번은 교과서처럼 `shoes[2] = 260` 줄만 주고 출력 부분은 빈칸 뼈대로, 실행 칸은 비움.
- 128쪽 스스로 해결하기: 하의 치수 표(문제 자료)만 넣고 1~3번은 빈칸 뼈대 + 힌트, 실행 칸은 비움(정답 코드 없음).
- 더 해 보기(선택): 나만의 리스트(append 두 번), 없는 인덱스를 쓰면 어떤 오류가 나는지, 나만의 딕셔너리. 딕셔너리에 없는 키를 쓰는 실험은 다음 차시(130쪽 스스로 해결하기 1번)의 질문이라 넣지 않음.

**줄인 것** — 126쪽 삽화는 넣지 않음. 그림 Ⅲ-8의 3차원은 반별 표 세 장을 겹친 그림으로만(숫자는 생략). 127·128쪽 스스로 해결하기는 화면에 문제를 다시 쓰지 않고 노트북에서만 다룸. 01·02·03의 체험은 교과서와 다른 새 자료(줄넘기 기록, 동아리)로 만듦. 개념 정리하기는 교과서 131쪽 문장을 옮기지 않고 새 상황 문장 빈칸으로.

**확인할 점**
- 127쪽 「순서가 없는 컨테이너형으로는 딕셔너리」(119쪽 표도 「순서가 없다」): 파이썬 3.7부터 딕셔너리는 넣은 순서를 기억해 출력도 그 순서대로 나옴(교과서 128쪽 실행 결과도 넣은 순서대로). 교과서의 뜻은 「인덱스(위치 번호)로 찾지 않고 키로 찾는다」로 보여, 화면 비교 카드에 「위치 번호가 아니라 키로 찾아요」를 덧붙임.
- 127쪽 스스로 해결하기 1번은 학생용 교과서에서 값이 빈칸인데, 교사용 교과서와 교과서코드 파일(`127_스스로_해결하기_1번.py`, `_2번.py`)에는 예시 값이 있고 두 파일의 첫 값도 서로 다름. 노트북은 학생이 값을 정하게 함.
- 127쪽 Tip의 「append() 명령어」 — 제작 지침의 「메소드」 표기와 다르지만 교과서 쪽 표현(append())을 그대로 씀.
- 01의 그림 Ⅲ-8 1차원 이름(내빈·미송·민수·준서)은 교과서 그림 그대로. 129쪽 표에서는 3번 학생이 「인수」로 나옴(다음 차시 확인할 점).

**검토 반영(1차)**
- 131쪽 개념 정리와 같은 문장을 사례형으로: 퀴즈 1-1(여러 개의 1차원 데이터가 모이면? → 학생별 [상의, 신발, 하의] 묶음을 반 전체만큼 모은 데이터는?, 정답 ②→③), 마무리 5-1(1차원 데이터를 표현하는 자료형은? → 요일별 기온 7개를 한 변수에 묶을 자료형은?, 정답 ③→②), 04 개념 정리 2번(temp 기온 리스트와 반별 표로, 「컨테이너형」 빈칸 대신 「2차원 데이터」 빈칸). key3 첫 칸도 문장 구조를 바꿈.
- 퀴즈 3-3 오답 「중복된 키를 여러 개 쓸 수 있다」가 3-2(이미 있는 키로 저장하면?)의 단서라 「값을 넣은 차례 번호로 찾는다」로 바꿈.
- 리스트/딕셔너리 고르기 카드 6장의 끝말(리스트=「적어요/모아요」, 딕셔너리=「찾아봐요」)과 「이름으로 찾다」 표현을 섞어 끝말·낱말로 답이 드러나지 않게 다시 씀.
- 화면 체험의 값 표시(pyRepr)를 파이썬과 똑같게 고침: 숫자 키는 따옴표 없이(`{0: [1, 3]}`), 딕셔너리 키는 넣은 순서대로(숫자 키도 `DK()`로 순서 유지), 작은따옴표가 든 문자열은 `"it's"`처럼 표시. 네 차시 lesson.js에 같은 코드로 넣고 python3 출력과 대조함.
