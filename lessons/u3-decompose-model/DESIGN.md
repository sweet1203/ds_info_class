퀴즈 15문항(정답 위치 ①5 ②5 ③5).

**질문폼(info-u3-decompose-model)** — 1번 ← 01 장면 고르기·로봇 명령(`robotRun`)·해결 가능 분류, 2번 ← 03 퍼즐(`puzzleHow`)·내 문제 나누기(`decompMine`), 3번 ← 04 지하철 그래프(`routeFew`·`routeFast`).

**50분 흐름(검토 반영 후)** — 도입(2분) 단원 핵심 질문만 짚고 알고 있나요 칩, `planGame` → 01(7분) 문제 상태 카드, 장면 고르기, 로봇 명령 짜기(질문폼 1번 근거, 9분 무렵 끝), 해결 가능 분류 6장 → 02(5분) 과정·용어 카드 훑기, 알고리즘 한 단계씩(끝까지 실행 버튼 가능), 핵심 요소 고르기 → **03(14분 무렵 시작, 7분)** 날짜 상자 다음 ▶ 6번, 퍼즐은 **구역 1·2만 필수**, 내 문제 나누기(질문폼 2번 근거, 21분 무렵) → **04(21분 무렵 시작)** 지도 지우기, 경로 두 개 기록(질문폼 3번 근거, 27분 무렵까지) → 규칙 모델링 글 읽기(타일 무늬는 선택으로 접음) → 개념 정리(3분) → 마무리(9분). 퍼즐 나머지 구역·타일 무늬·쾨니히스베르크는 시간이 남을 때.

**줄인 것** — 89~92쪽 그림·만화, 핵심 역량 목록은 넣지 않음(단원 소개 문장·핵심 질문·기사 요약만). 92쪽 그림 자료(명화, 게임 화면)는 빼고 생각해 볼까요 글만 요약. 93쪽 로봇 예제 화면 그림은 새 격자로 다시 만듦. 93쪽 사례 1·2와 생각해 보기(사례 3)는 같은 문장을 쓰지 않고 새 문제 6개 분류로 바꿈. 94쪽 (가) 사진은 SVG 그림으로, (나)는 같은 규칙을 되풀이한 그림을 코드로 그림. 95쪽 날짜는 새 날짜로. 96쪽 퍼즐은 새 퍼즐로(교과서 퍼즐·풀이 칸 옮기지 않음). 97쪽 위성 지도·서울 지하철 노선도는 가상 도시 지도로. 98쪽 삼각형 예제는 다른 무늬(정사각형 타일)·다른 수로. 쾨니히스베르크는 그래프 모델 답을 넣지 않고 오일러 규칙과 선택 메모만. 101쪽 개념 정리하기(이 차시 용어)는 교과서 문장을 옮기지 않고 새 상황 문장 빈칸으로 04에 둠.

**선생님 준비물** — 없음(브라우저 안에서 모두 체험). 94쪽 turtle 코드는 화면에 보여 주기만 하고 실행은 하지 않음(파이썬 실습은 이후 변수·입출력 시간에 시작).

**확인할 점**
- 95쪽 「완료」 줄의 첫 상자가 「1-1」로 인쇄됨(PDF 직접 확인). 앞 단계의 데이터는 「1-5」이므로 오타로 보임. 화면 체험은 새 날짜를 써서 영향 없음.
- 94쪽 (라) 4단계 「선 길이를 70% 줄이기」는 (마) 코드 `len = len * 0.7`(원래 길이의 70%가 됨)과 뜻이 어긋남(70%를 줄이면 30%가 남음). 화면에는 「선 길이를 70%로 줄이기(0.7배)」로 바로잡음.
- 94쪽 코드의 변수 이름 `len`은 파이썬 내장 함수 `len()`과 이름이 같음. 실행에는 문제가 없지만, 이후 리스트 단원에서 `len()`을 배울 때 헷갈릴 수 있음(화면은 교과서 그대로 둠).
- 98쪽 오일러의 한붓그리기 ❸ 「홀수 점이 1개이거나 3개 이상이면」 — 그래프에서 홀수 점의 개수는 늘 짝수라서 「1개」인 경우는 생기지 않음. 접어 둔 선택 활동에 교과서 문장 그대로 둠(수업 중 질문이 나오면 설명 필요).
- 98쪽 삼각형 예제의 표와 결과는 계산이 맞음을 확인함. 화면 체험은 다른 무늬로 바꿨고 규칙의 모양(앞 결과 + 새로 붙는 수)은 교과서와 같음.
- 93쪽 문제 상태 설명은 「초기 상태와 목표 상태를 나타낸다」라고 하면서 현재 상태도 함께 설명함. 화면은 세 상태를 모두 카드로 보여 줌.

**검토 반영(1차)**
- 분량: 퍼즐은 구역 1·2(위 두 행)만 필수로 하고 확인 버튼이 「필수 구역 1·2 완성」을 따로 알려 주고 기록(`puzzleDone`). 타일 무늬 규칙 찾기는 「선택」으로 접고, 펼친 화면에는 98쪽 규칙 모델링·자동화 설명 문장만 둠. 도입의 소행성·게임 설명을 줄임. 지하철 체험(질문폼 3번 근거)이 27분 무렵에 끝나도록 50분 흐름을 다시 잡음.
- 04 개념 정리 빈칸: 101쪽 개념 정리하기와 정의 꼬리가 같던 문장을 「상황 → 이렇게 한 일은 ( )이다」 꼴의 상황 문장으로 바꿈.
- 로봇 체험 제목을 「교과서 예제와 같은 명령 5개, 새 규칙·새 격자」로(한 칸 점프의 뜻을 새로 정했으므로).
- 지하철 문제 ①(환승 최소)의 기록에서 걸린 시간을 뺌(①은 시간 정보를 쓰지 않는 모델).
- 퀴즈: 2-2 해설이 5-1(과정 순서)의 답을 그대로 보여 주던 것을 고침. 1-1 해설에서 현재 상태 설명을 빼고, 타일 규칙을 줄기에 담았던 4-3은 「학교 → 도서관 한 정거장 이동 뒤 = 현재 상태」(화면 지도 기준) 문항으로 바꿈(접은 타일 활동을 묻지 않음). 5-3 줄기를 펼친 화면의 규칙 모델링 문장에 맞춤.
- 시작 화면 「오늘 01~04에서 다시 만나요」를 실제로 나오는 「문제 상태와 핵심 요소 추출은 오늘 01~02에서」로 고침.
- 확인할 점 추가: 101쪽 개념 정리하기 「(모델링)은 복잡한 상태를 단순하게 구조적으로 표현한 결과이다」는 97쪽 본문(「모델」이 결과, 그 모델을 만드는 「과정」이 모델링)과 어긋남. 화면은 본문을 따라 모델 = 결과, 모델링 = 과정으로 씀.

**검토 반영(2차)**
- 퀴즈 4-3 줄기를 화면 지도에 맞게 「학교역에서 공항역으로 가는 문제에서 학교 → 도서관으로 한 정거장 이동한 뒤의 상태」로 고침.
- 퀴즈 1-3 오답을 늘려(「문제를 낸 사람의 이름과 학년」 등) 정답만 긴 길이 단서를 없앰.
- key3 문제 분해 문장을 「큰 문제를 풀기 쉬운 작은 문제 여러 개로 쪼개는 일」로 풀어 씀.
