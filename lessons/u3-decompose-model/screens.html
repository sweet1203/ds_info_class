「NASA도 놓친 지구 위협 소행성, 새 알고리즘이 찾았다!」
미국 워싱턴대학교 연구진이 새로 개발한 소행성 탐지 프로그램 「헬리오링크3D」가 약 183미터 길이의 소행성 「2022 SF289」를 찾아냈어요. 기존 탐지 시스템도 미처 발견하지 못한 소행성이었지요. 연구 책임자는 지금까지 규명된 소행성 개수를 찾는 데 200년이 넘게 걸렸지만, 이를 두 배로 늘리는 데에는 3개월~6개월이면 될 것이라고 말했어요.

오늘은 복잡한 문제를 컴퓨팅 시스템으로 해결하기 위해 문제의 상태를 정하고, 추상화로 핵심 요소를 뽑고, 문제 분해로 작은 문제로 나누고, 모델링으로 구조화하는 과정을 직접 해 봐요.

단원 도입 · Ⅲ. 알고리즘과 프로그래밍

효율적인 알고리즘 설계와 프로그래밍을 통한 자동화는 다양한 분야의 문제를 해결하는 데 도움을 줘요. 이 단원에서는 문제를 효율적으로 해결하기 위해 먼저 문제를 추상화해 알고리즘을 설계하고, 프로그램을 구현하기 위해 거치는 프로그램 작성, 실행 결과 평가, 오류 수정 같은 자동화 과정을 배워요. 이를 바탕으로 컴퓨팅 사고력(추상화 능력, 자동화 능력, 창의·융합 능력)을 길러요.

알고 있나요? 중학교 『정보』에서 배운 것 가운데 기억나는 것을 모두 골라요. 문제 상태와 핵심 요소 추출은 오늘 01~02에서 다시 만나요.

게임의 규칙과 다양한 요소를 컴퓨터 명령어로 구현해 재미있는 컴퓨터 게임을 만들려면 어떤 과정을 거쳐야 할까?

01

컴퓨팅 시스템으로 해결할 수 있는 문제

교과서 93쪽 · 문제, 문제의 상태(초기·현재·목표), 수행 과정

쉽게 말하면문제가 어디서 시작해(초기 상태) 어디에 도착해야 하는지(목표 상태), 그리고 무엇을 하면 되는지(수행 과정)를 분명하게 말할 수 있으면 컴퓨터에게 맡길 수 있어요.

💡 문제와 문제의 상태

문제는 해답을 요구하는 물음 또는 해결해야 하는 일이나 상황 등을 뜻해요. 원하는 결과를 얻거나 문제 상황에서 벗어났을 때 문제가 해결되었다고 해요. 문제의 상태는 이렇게 나타내요.

🚩

초기 상태

문제가 발생한 최초의 상태

🔄

현재 상태

문제가 한 번에 해결되지 않고, 해결하면서 변화되고 있는 상태

🏁

목표 상태

문제가 해결된 상태

컴퓨팅 시스템을 활용해 문제를 해결하려면 문제 해결 과정을 컴퓨터가 이해할 수 있는 언어로 표현해야 해요. 그래서 문제의 초기 상태, 목표 상태, 수행 과정을 명확하게 설명할 수 있어야 해요.

🤖 체험 · 로봇이 파란 타일에 불을 켜는 문제 (교과서 예제와 같은 명령 5개, 새 규칙·새 격자)

① 아래 세 장면 가운데 초기 상태와 목표 상태를 골라요. ② 명령 5개만 써서 로봇이 파란 타일로 가 불을 켜게 해요.

🎯 컴퓨팅 시스템으로 해결할 수 있을까?

문제 6개를 읽고 골라요. 「처음과 끝, 하는 일을 분명하게 정할 수 있을까?」를 먼저 생각해요.

해결 과정을 프로그래밍 언어로 자동화하면 다른 문제에도 활용할 수 있어요. 예를 들어 온도에 따라 작동 여부를 자동으로 제어하는 과정을 프로그래밍해 일반화하면, 선풍기·냉장고 같은 다양한 제어 프로그램으로 확장할 수 있어요.

02

문제 해결 과정과 추상화

교과서 94쪽 · 복잡한 문제, 핵심 요소, 추상화, 알고리즘 설계와 프로그래밍

쉽게 말하면진짜 나무를 그대로 그리라고 하면 너무 복잡해요. 줄기와 가지처럼 꼭 필요한 것만 남기면(추상화) 규칙을 만들 수 있고, 규칙을 순서대로 적으면 알고리즘, 그것을 프로그래밍 언어로 쓰면 프로그램이 돼요.

🛤️ 프로그래밍으로 문제를 해결하는 과정

문제 이해→핵심 요소 추출→문제 분해 및 모델링→알고리즘 설계→프로그래밍

복잡한 문제

어려운 문제와는 다른 의미로, 여러 번의 절차를 거쳐서 해결해야 하는 문제예요.

핵심 요소

초기 상태에서 목표 상태로 나아가기 위해 반드시 고려해야 하는 요소예요. 고려하지 않으면 문제를 해결할 수 없거나 해결하는 데 매우 오래 걸릴 수 있어요.

알고리즘

문제를 해결하기 위한 일련의 단계적 절차나 방법이에요. 페르시아 수학자 알-콰리즈미의 이름에서 유래했어요.

🌳 예제 · 나무 그리기 문제의 추상화 (그림 Ⅲ-2를 다시 그림)

(가) 복잡한 문제이미지의 각 픽셀에 색상값을 저장해 표현 → 해결 과정을 논리적으로 설명하기 어려워요.
(나) 핵심 요소 추출핵심 요소만 남겨 표현 → 컴퓨팅 시스템으로 해결할 수 있는 문제로 만들어요.
(다) 문제 분해 및 모델링작은 문제로 분해해 표현 → 직선 줄기 한 개와 왼쪽 가지, 오른쪽 가지

컴퓨팅 시스템을 활용한 문제 해결에서 복잡한 문제의 불필요한 요소를 제거하고 핵심 요소만 남기는 것을 추상화라고 해요. 줄기와 왼쪽 가지, 오른쪽 가지의 크기와 모양에 적용되는 규칙을 절차적으로 만들어 프로그래밍 언어로 표현하면 컴퓨팅 시스템으로 해결할 수 있어요.

▶️ 체험 · 알고리즘 한 단계씩 실행하기 (그림 Ⅲ-3 (라) 알고리즘 설계 · (마) 프로그래밍)

한 단계 ▶를 누를 때마다 알고리즘 한 줄과 그 줄을 옮긴 코드가 함께 실행돼요. 거북이(▲)가 움직이는 모습을 보며 두 표현을 맞춰 봐요.

교과서 코드는 파이썬의 turtle(거북이 그래픽)로 그려요. 「프로그래밍은 파이썬 설치 후 실행해 봅시다」(119쪽)처럼 파이썬에서 직접 실행해 볼 수도 있어요.

✂️ 핵심 요소 고르기 · 학교 축제 길 안내 앱

축제에 온 손님이 정문에서 원하는 부스까지 찾아가도록 돕는 길 안내 앱을 만들려고 해요. 이 문제를 해결하는 데 반드시 고려해야 하는 요소만 골라 누르고 확인을 눌러요.

03

문제 분해

교과서 95~96쪽 · 문제 분해, 분할 정복, 스스로 해결하기, 지식 키우기

쉽게 말하면한 번에 풀기 어려운 문제는 해결하기 쉬운 작은 문제로 나누면 실마리가 보여요. 작은 문제를 하나씩 해결해 합치면 전체 문제가 해결돼요.

🧩 문제 분해와 분할 정복

문제가 복잡해 해결 방법을 쉽게 찾을 수 없을 때, 작은 문제로 나누는 문제 분해로 실마리를 찾을 수 있어요. 문제 분해란 복잡한 문제를 해결하기 쉬운 작은 문제로 나누는 것이에요. 그 후 효과적인 알고리즘을 설계해 컴퓨팅 기술로 해결해요.

분할 정복은 복잡한 문제를 작은 문제로 나눈 뒤 각각의 작은 문제를 해결해 전체 문제를 해결하는 전략이에요. 1805년 아우스터리츠 전투에서 나폴레옹이 자기 군대보다 많은 연합군의 중앙으로 쳐들어가 병력을 둘로 갈라놓아 승리한 데서 유래했어요.

📦 체험 · 날짜 상자를 분할 정복으로 정리하기 (교과서 95쪽과 같은 방법, 새 날짜)

「월-일」 날짜 라벨이 붙은 상자 8개를 날짜가 빠른 순서대로 정리해요. 분할은 더 이상 나눌 수 없을 때까지 둘로 나누고, 정복은 작은 문제 두 개의 첫 번째 데이터끼리 비교하며 합쳐요.

🔬 스스로 해결하기 · 복잡한 문제 분해 (숫자 퍼즐)

필수: 맨 위의 구역 1·2(굵은 선 안의 왼쪽 위·오른쪽 위)만 채우고 확인을 눌러요. 나머지 구역은 선택(시간이 남을 때)이에요. 각 행, 각 열, 굵은 선으로 나눈 각 구역에 1부터 6까지 숫자가 모두 한 번씩 나타나야 해요. 퍼즐 전체를 한꺼번에 보지 말고, 아래 버튼으로 구역·행·열 하나씩 작은 문제로 나누어 빈칸을 채워요.

🙋 지식 키우기 · 내 문제를 작은 문제로 나누기 (96쪽)

「일상생활에서 해결할 수 있는 문제를 찾아 프로그램 제작하기」라는 모둠 과제는 자료 수집, 발표 자료 제작, 프로그램 작성, 발표 등으로 나누어 모둠원이 역할을 맡아 해결할 수 있어요. 모둠 과제에서 역할을 나누는 것도 문제 분해예요.

아래에서 큰 문제 하나를 고르고, 해결하기 쉬운 작은 문제 3~4개로 나누어 적어요.

04

모델링

교과서 97~98쪽 · 모델과 모델링, 그래프로 모델링하기, 문제 상태 모델링, 규칙 모델링

쉽게 말하면모델은 복잡한 상태를 단순하게 구조적으로 표현한 결과이고, 모델을 만드는 과정이 모델링이에요. 지하철 노선도처럼, 문제를 푸는 데 필요한 정보만 골라 관계를 그려 놓는 거예요.

🗺️ 모델과 모델링

모델이란 모형이나 축소형이라는 뜻으로, 복잡한 상태를 단순하게 구조적으로 표현한 결과예요. 이러한 모델을 만드는 과정을 모델링이라고 해요. 컴퓨팅 시스템을 활용한 문제 해결에서는 복잡한 문제에서 추출한 핵심 요소들의 관계를 구조화해 이해하기 쉬운 형태로 표현해요.

모델링은 글, 그림, 기호, 수식, 표 등 다양한 방식으로 할 수 있어요. 문제의 초기 상태부터 목표 상태까지의 수행 과정을 절차적으로 모델링하면 알고리즘 설계가 쉬워져요. 같은 지도라도 문제가 바뀌면 핵심 요소가 달라져서 모델링 결과도 달라져요.

🚇 체험 · 그래프로 모델링하기 (교과서 97쪽의 생각해 보기를 새 지도로)

가상의 도시에서 지하철로 학교역에서 공항역까지 가려고 해요. ① 먼저 필요 없는 정보 지우기를 눌러 지도를 모델로 바꿔요. ② 학교역에서 시작해 이웃한 역을 차례로 눌러 경로를 만들어요. 환승이 가장 적은 경로와 시간이 가장 짧은 경로를 하나씩 찾아 기록해요.

핵심 문장 · 처음 생각과 비교 · 마무리 퀴즈 · 질문폼

문제의 상태는 초기 상태, 현재 상태, 목표 상태로 나타낸다. 초기 상태, 목표 상태, 수행 과정을 명확하게 설명할 수 있는 문제는 컴퓨팅 시스템으로 해결할 수 있다.
프로그래밍으로 문제를 해결할 때는 문제 이해 → 핵심 요소 추출 → 문제 분해 및 모델링 → 알고리즘 설계 → 프로그래밍 과정을 거친다. 불필요한 요소를 제거하고 핵심 요소만 남기는 것이 추상화이다.
문제 분해는 큰 문제를 풀기 쉬운 작은 문제 여러 개로 쪼개는 일이고, 모델링은 핵심 요소들의 관계를 구조화해 단순하게 표현하는 과정이다. 문제가 바뀌면 핵심 요소와 모델도 달라진다.
