## 50분 흐름 (시작 화면 「50분 계획」과 같음)
모둠 정하기(2분) → 01 문제 발견 · 추상화(9분, ~11분) 사례는 힌트 카드로 짧게(검색은 선생님 안내 범위), 문제 정의, 관련 요소 칩, 입력·출력, 데이터 표 훑기 → **02 알고리즘 설계(12분, ~23분)** ③부터 단계 쓰기 → 순서도 확인, 함수 설계, 프로젝트 카드 완성(생성형 인공지능 질문은 접어 둠) → **03 진로(5분, ~28분)** 인터뷰 카드 · 진로 카드 → 04 발표 준비(8분, ~36분) 카드 보고 1분 발표 연습, 특정 날짜 토의 메모, 자기 평가(실제 발표·동료 평가는 선생님 운영: 시간이 되는 모둠만 또는 다음 시간 앞부분) → 05 단원 정리(8분, ~44분) 분류 게임 · 퀴즈 → 마무리(6분) 질문폼.

## 노트북 `assets/mars_travel.ipynb` (선택 · 다음 시간)
0 모둠 설계 옮겨 적기(마크다운) → 1 행성 데이터(156쪽 딕셔너리 그대로 + 탐색 출력, 값 꺼내 보기 빈 셀) → 2 입력 받기 → 3 여행 시간 함수 → 4 결과 출력 → 5-❶ 결과 확인(함수 이름이 travel_time일 때 예시로 호출하는 셀, 없으면 안내 문장) · 5-❷ 토의 정리(마크다운) → 6 더 해 보기(모든 행성 반복 출력, 속도 바꾸기, 공전 주기로 출발 날짜 고려). 2~4·6은 **빈 셀 + 접힌 힌트**(입력 요소, 형 변환, in으로 키 확인 / 함수 모양, 거리 가정, 단위, 음수 / round·f-문자열)이고 정답 코드는 넣지 않았다. 출력은 비운 채 저장. 로컬 python3로 모든 셀을 실행해 오류가 없음을 확인했고(빈 상태에서는 확인 셀이 안내 문장을 출력), 저장소 밖 시험용 함수를 끼워 확인 셀이 동작하는 것도 확인했다.

## 확인할 점
- 156쪽 3단계는 ①, ②만 주고 「나머지 부분을 채워 완성」하라고 하며, 4단계 데이터에는 **태양까지의** 평균 거리만 있다. 지구에서 행성까지의 거리를 어떻게 정할지는 교과서에 없어, 노트북 힌트 2에 「모둠이 가정을 세워 주석으로 적는다」로만 안내하고 실제로는 행성이 공전해 거리가 계속 바뀐다는 점을 5-❷ 토의(특정 날짜 출발)와 이어 둠. 화면에는 계산 결과(일수)를 보여 주지 않음.
- 우주선 속도 값은 교과서에 없어 모둠이 정해 입력하게 함(실제 탐사선 속도를 쓰려면 찾은 자료의 출처를 적게 함). 화면에 실제 탐사선의 이동 기간 같은 수치는 넣지 않음.
- 158쪽 인터뷰 「포기하기 않고」는 「포기하지 않고」의 오타로 보여 화면에는 바르게 씀. 인터뷰는 3문답을 줄여 썼고 「희열」 같은 표현은 「큰 보람」으로 풀어 씀.
- 154쪽 1단계는 「인터넷에서 찾아」, 155쪽 ❷는 「생성형 인공지능을 이용할 수도」라고 안내하지만 학교에서 쓸 수 있는 도구가 정해져 있지 않아 「선생님 안내에 따라」로 씀.
- 05 용어 카드는 93~153쪽 소단원 「주요 용어」(문제 상태, 문제 해결 과정, 문제 분해, 모델링, 추상화 / 정렬, 버블 정렬, 삽입 정렬, 퀵 정렬 / 순차 탐색 알고리즘, 이진 탐색 알고리즘 / 변수, 자료형 / 표준 입력, 표준 출력, 표준입출력, 파일입출력 / 다차원 데이터, 1차원 데이터, 2차원 데이터 / 제어 구조, 선택 구조, 반복 구조, 중첩 제어 구조, 함수 / 객체, 클래스, 객체지향 프로그래밍, 인스턴스, 메소드)와 본문 용어(수행 시간, 기억 공간, 리스트, 딕셔너리)를 따름. 같은 단원 다른 차시(u3-decompose-model ~ u3-function, 다른 담당이 만드는 중) 화면 용어와 다르면 그쪽에 맞춰 고쳐야 함. 퀴즈 · 분류 카드 소재가 그 차시들의 퀴즈와 겹치는지도 총괄 검토에서 확인이 필요함.
- 단원 핵심 질문은 88쪽 두 질문(알고리즘 / 프로그래밍)을 시작 화면에 두고, 마무리 메모는 프로젝트와 이어지는 프로그래밍 질문 하나만 받음(u1 · u2-review와 같은 방식).
- 159쪽 역량 Check의 12개 역량은 u1 · u2-review와 같은 목록(교과서 159쪽과 동일)을 씀.
