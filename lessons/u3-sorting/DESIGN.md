퀴즈 16문항(정답 위치 ①5 ②5 ③6).

**질문폼(info-u3-sorting)** — 1번 ← 01 대출자·미납자 목록 비교(`libRec`·`libWhy`), 2번 ← 02 버블 정렬 시뮬레이터(`bubbleRec`), 3번 ← 02~03 정렬된·역순 리스트 기록(`bubbleRec`·`insertRec`·`caseCmp`).

**시뮬레이터 규칙(교과서와 같게 맞춘 것)**
- 버블 정렬: 교과서처럼 이미 정렬되어도 n − 1단계를 모두 수행(비교 n(n − 1)/2번). 교과서 예(10, 6, 2, 4, 3)에서 단계별 비교·교환 수가 교과서 103쪽과 같음.
- 삽입 정렬: 삽입할 요소를 바로 앞 요소와 비교해 앞 요소가 크면 교환하며 앞으로 옮김. 정렬된 리스트 n − 1번 비교, 역순 n(n − 1)/2번 비교·교환으로 교과서 표와 같음.
- 퀵 정렬: 첫 요소 pivot, 두 번째 low, 마지막 high. low는 pivot 이하인 값을 지나 오른쪽으로(리스트 끝은 넘지 않음), high는 pivot보다 큰 값을 지나 왼쪽으로 이동. low < high면 교환, 아니면 pivot과 high 교환·고정, 왼쪽 영역 → 오른쪽 영역 순서. 교과서 예의 모든 단계(1단계~3단계, 「low와 high가 같아짐」 포함)가 교과서와 같게 나옴. 무작위 리스트 2,000개로 세 정렬 결과가 맞음을 node로 확인함.
- 퀵 정렬의 비교·교환 횟수는 교과서에 세는 방법이 없어 화면에 「이 화면에서 세는 방법」을 밝힘(low·high가 값을 pivot과 견준 횟수, 실제로 자리를 바꾼 횟수).

**50분 흐름** — 도입(3분) 도입 질문·`planSort` → **01(7분)** 파일·레코드·필드·키 카드, 키 표 눌러 보기, 목록 맞춰 보기 ①② 실행·메모(질문폼 1번 근거, 10분 무렵 끝) → **02(8분)** 교과서 예를 예측하며 진행(18분 무렵 끝) → 정렬된·역순 리스트를 「끝까지」로 실행해 기록 → **03(6분)** 교과서 예 진행, 정렬된·역순 기록, `caseCmp`(질문폼 3번 근거, 24~26분 무렵) → 04(8분) 교과서 예 단계와 교과서 문장 맞춰 보기, 정렬된·가운데 값 리스트 비교 → 05(7분) 세 정렬 비교 2~3번, 빈칸 → 마무리(8분). 107쪽 손으로 쓰기는 시간이 부족하면 숙제나 다음 시간 시작으로.

**줄인 것** — 102쪽 동물 그림·고객 표는 가상의 도서실 대출 기록 표로 바꿈(교과서 고객 이름은 쓰지 않음). 103~106쪽 단계 그림은 막대 시뮬레이터로 대신하고, 교과서 예 리스트는 교과서와 비교하라고 그대로 둠. 106쪽 퀵 정렬 최선의 경우 트리 그림은 글(n/2, n/4로 반씩 나뉨)로만. 107쪽 함께 해결하기의 힌트 그림은 옮기지 않고, 교과서 리스트는 화면에 쓰지 않음(공책에 먼저 쓰고 시뮬레이터 직접 입력으로 확인). 107쪽 개념 정리하기는 교과서 문장 대신 새 상황(줄 서기) 문장 빈칸으로.

**선생님 준비물** — 없음. 107쪽 함께 해결하기는 공책(또는 학습지)에 손으로 써 보게 하면 좋음.

**확인할 점**
- 103쪽 「이 과정은 1단계 정렬이 완료될 때까지 n − 1번 수행된다」는 뜻이 애매함(한 단계 안의 비교가 n − 1번인지, 단계가 n − 1번인지). 그림은 요소 5개를 4단계로 정렬하므로 화면에는 「요소가 n개이면 n − 1단계 수행」으로 씀.
- 104쪽 본문은 최악의 경우 「비교와 이동」이 1 + 2 + … + (n − 1)번이라 하고, 표는 「교환 횟수」로 씀. 화면 시뮬레이터는 교환으로 옮기는 방식이라 표의 「교환 횟수」를 그대로 씀(시뮬레이터 설명에 밝힘).
- 105쪽 1단계 네 번째 줄 그림의 low·high 화살표가 서로 바뀌어 있음(그림은 low가 ‘2’, high가 ‘10’ 아래). 「low가 high보다 커짐」과 다음 줄 「pivot과 high 교환」(4와 2를 교환)을 보면 low가 ‘10’, high가 ‘2’ 위치여야 맞음. 시뮬레이터는 본문대로 표시함.
- 106쪽 3단계 첫 영역(10, 6, 7)은 low가 리스트 끝에서 멈춰 「low와 high가 같아짐」이고, 다음 영역(7, 6)은 low가 영역 밖의 ‘10’까지 가서 「low가 high보다 커짐」임. 두 경우를 함께 설명하려면 「low는 리스트의 끝을 넘어가지 않는다」는 규칙이 필요해 화면에 작게 밝힘.
- 105쪽 본문은 「분할 영역의 크기가 1 이하가 될 때까지」, 수행 과정 설명은 「크기가 1이 될 때까지」라고 씀. 뜻은 같아 화면은 본문을 따름.
- 퀵 정렬의 수행 시간은 교과서가 O 표기로 쓰지 않아 화면에도 O 표기를 넣지 않음(최선·최악을 피벗 위치로만 설명).

**검토 반영(1차)**
- 퀵 정렬 교환을 두 단계로 나눔: 「low = 6, high = 1 교환」 단계는 교환 전 배열과 low·high 위치를, 다음 「교환 결과」 단계는 바뀐 배열을 보여 줌(교과서 105쪽 그림의 줄 구성과 같음). 교과서 예 전체 단계를 node로 다시 확인하고, 무작위 리스트 3,000개로 세 정렬 결과를 다시 검산함.
- 퀵 정렬 셈 기준은 우리 기준을 유지하고 「세는 방법이 다르면 값도 달라지므로, 손으로 세면 이 화면과 다를 수 있어요」를 덧붙임. 05 비교에 「무작위는 n = 32로도 해 보세요」 추가. 107쪽은 공책에 먼저 쓰는 방식 유지.
- 삽입 정렬 예측 모드: 예측 전 화면에서 삽입할 요소(굵은 테두리)가 교환 뒤 위치에 그려지던 버그를 고침(교환 전 위치 `preKey` 사용). 같은 값끼리 비교할 때 「더 작아 제자리」라고 나오던 문구를 「○보다 크지 않아 제자리」로.
- 퀴즈: 4-3 오답 「맨 처음 요소가 피벗일 때」(교과서는 늘 첫 요소가 피벗이라 애매)를 「가장 작은 요소가 피벗일 때」로. 3-1 오답에서 「피벗」을 빼고 정답이 가장 긴 보기가 되지 않게 보기를 바꿈. 6-1도 정답이 가장 긴 보기가 되지 않게 바꿈. 6-3 해설의 「다음 시간에」를 뺌. 정답 위치를 다시 맞춤(①5 ②5 ③6).
- 마무리 key3 둘째·셋째 문장을 107쪽 개념 정리하기와 다른 구조(옆 요소끼리 견주어… / 피벗 하나를 기준으로 갈라놓고…)로 다시 씀.
