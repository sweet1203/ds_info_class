# u2-review 설계표 — 협력적 창의·융합 프로젝트 · Ⅱ단원 정리 (교과서 84~87쪽)

u1-review와 같은 틀(문제 발견 → 설계 → 진로 → 발표 준비 → 단원 정리, 동료 평가·역량 Check는 선택으로 접기)로 만들었다. 50분 한 차시 안에서 모둠 프로젝트 **기획**(문제 → 필요한 데이터·수집 방법 → 전처리 → 시각화 계획 → 기대 효과)과 **발표 준비**까지 하고, 실제 데이터 수집·발표·동료 평가는 선생님 운영에 맡긴다. 모둠 활동이지만 메모는 각자 화면에 적는다(질문폼은 개인).

질문폼(info-u2-review) 1번 ← 01 `problem` `needData` + 02 `collectPickName` `collectHow`, 2번 ← 02 `prepPickName` `prepHow` `vizPickName` `vizHow` `effect`, 3번 ← 03 진로 카드 `career` `careerSkillPick`(진로를 발표 준비 앞에 두어 22~27분에 닿게 함).

## 50분 흐름 (시작 화면 「50분 계획」과 같음)
모둠 정하기(2분) → 01 문제 상황 이해(6분, ~8분) → **02 데이터 분석 계획(14분, ~22분)** 칩 고르기, 수집·전처리·시각화·기대 효과 적기, (선택) 스케치, 프로젝트 카드 완성 → **03 진로(5분, ~27분)** 인터뷰 카드·진로 카드 → 04 발표 준비(8분, ~35분) 프로젝트 카드 보고 1분 발표 연습·성찰(압축·암호화)·자기 평가(실제 발표·동료 평가는 선생님 운영: 시간이 되는 모둠만 또는 다음 시간 앞부분) → 05 단원 정리(8분, ~43분) 분류 게임·퀴즈 → 마무리(7분) 질문폼.

## 줄인 것
- 84~85쪽 프로젝트는 원래 데이터를 실제로 수집·전처리·시각화·분석하는 활동이지만, 50분 안에 어려워 **계획 + 시각화 스케치(예상 값 가능)**까지로 줄였다. 실제 데이터로 하려면 오렌지3와 선생님이 알려 주는 공공 데이터 사이트로 다음 시간에 이어서 할 수 있다(프로젝트 카드가 그대로 계획서가 됨).
- 84~85쪽에 채워진 「예」는 교과서 예시 답안이라 화면과 이 문서에 옮기지 않았다. 입력 칸 예시는 다른 소재(휴가철 고속도로 졸음운전, 시간대·도로 구간 등)로 쓰고, 마무리 퀴즈의 시각화 문항도 예시와 겹치지 않는 소재로 만듦.
- 87쪽 단원 정리 14문항은 형성평가 문항이므로 옮기지 않았다. 같은 개념(런 길이 부호화, 전치형 암호화, 빅데이터의 다양성, 데이터 합치기, 웹크롤링, 허프만 부호화, 단방향 암호화 등)을 **새 상황 문장**(학교 로고 그림, 글자 자리 뒤섞은 모둠 쪽지, 해수욕장 안전 관리 자료, 사고 기록 표와 피해 표, 뉴스 기사 제목 모으기 등)으로 퀴즈와 분류 게임에 넣음. 정답(238쪽)은 넣지 않음.
- 85쪽 평가하기의 자기 평가·동료 평가 표(웃는 얼굴 3단계)는 자기 평가 칩(잘한 것 고르기)과 동료 평가 메모(선택)로 바꿈. 평가 기준 문장은 접힌 표에 그대로 둠.
- 84쪽 수행 계획서 QR·모둠원 역할 표는 시작 화면의 모둠명·역할 메모로 대신함.

## 확인할 점
- 85쪽 4단계 「분석 및 결과 확인하기」에 채워진 예는 시각화한 데이터를 **분석한 결과**라기보다 **해결 방안·데이터 관리 방법**에 가깝다(5단계 「압축과 암호화 관점」과 겹침). 화면의 4단계는 「시각화로 확인하고 싶은 사실(예상)」과 「기대 효과」로 받았고, 압축·암호화 관점은 5단계 성찰에서만 다룸.
- 84쪽 사고 유형 「익사」는 교과서 그림 이름표 그대로 둠(학생에게 다소 무거운 낱말이라 소개 이야기에서는 「물에 빠지는 사고」로 풀어 씀).
- 86쪽 인터뷰는 「전망은 어떤가요?」 등 4문답을 줄여 썼고, 「무척 다양」 「지속적으로」 같은 표현을 풀어 씀. 퀴즈 보기에는 극단어가 들어가지 않게 함.
- 단원 핵심 질문은 46쪽 단원 도입의 두 질문(압축과 암호화 / 빅데이터)을 시작 화면에 두고, 마무리 메모는 프로젝트와 이어지는 빅데이터 질문 하나만 받음(u1-review와 같은 방식).
- 05 용어 카드의 압축·암호화 용어 목록은 51~63쪽 주요 용어와 본문 소제목을 따름(런 길이 부호화·사전 압축·허프만 부호화·JPEG·MPEG·치환형·전치형·단방향·대칭·비대칭·전자 서명). 같은 단원 다른 차시(u2-compression, u2-encryption)의 화면 용어와 다르면 그쪽에 맞춰 고쳐야 함.
- 87쪽 역량 Check의 12개 역량은 u1-review와 같은 목록(교과서 87쪽과 동일)을 씀.

## 검토 반영(1차)
- 퀴즈 2-2를 결측치(87쪽 5번과 비슷하고 u2-preprocess 2-1과 같은 보기·정답 위치)에서 **데이터 합치기 상황 문항**으로 바꿈(사고 기록 표와 피해 표를 사고 번호로 잇기, 정답 ③).
- 분량: 「확인하고 싶은 사실」(`expect`)과 「기대 효과」(`effect`)를 한 칸(`effect`)으로 합침. 04 발표는 4단 대본 틀과 긴 대본 칸을 빼고 「프로젝트 카드를 보고 말하기」(02 카드를 04에 다시 보여 줌) + 맡은 칸 한두 문장 메모로 줄임.
- 퀴즈 5-1 · 5-3 해설을 용어 정의 대신 상황 중심으로 고침(로고는 색과 반복 횟수만 적어도 되살릴 수 있음 / 센서가 1초마다 새 값을 보냄).
- 퀴즈 5-2가 u2-encryption 5-1(같은 키를 나눠 가진 두 친구 → 대칭)과 거의 같아, **전치형 상황**(글자는 그대로 두고 약속한 순서대로 자리만 뒤섞기)으로 소재를 바꾸고 보기 순서도 바꿈(치환형 · 전치형 · 단방향, 정답 ②).
- 분류 카드 「수학여행 영상 10GB…」(52쪽 10GB와 겹침)를 「체육대회 응원 사진 300장을 차이를 모를 만큼만 덜어 내 메신저로 보냄」으로 바꿈.
- 시각화 스케치 x축 이름표: 항목이 6개를 넘으면 이름표를 4글자로 줄이고, 9개를 넘으면 하나 건너 하나만 표시.
- 마무리 퀴즈 6-2 · 6-3의 보기 배치를 바꿔 전체 정답 위치를 ①3 ②3 ③4로 맞춤.
- 평가 기준표는 그대로 둠.

## 검토 반영(2차)
- 공용 chips 구분자(「 · 」) 문제로 칩 이름 「직접 수집(설문 · 촬영 · 센서)」 → 「직접 수집(설문, 촬영, 센서)」, 「히스토그램 · 분포도」 → 「히스토그램(분포도)」.
- 퀴즈 6-2가 u2-visualize 6-1과 보기·정답 위치가 같아 보기를 「원그래프 · 선그래프 · 박스 플롯」(정답 ②)으로 바꿈.
- 퀴즈 2-1(u2-bigdata-collect 4-1과 같은 「데이터가 없음 → 직접 수집」 구조)을 웹크롤링 상황(뉴스 누리집에서 기사 제목을 자동으로 모으기, 정답 ①)으로, 5-3(u2-bigdata-collect 1-2와 같은 속도 문항)을 다양성 상황(표·영상·글·녹음을 함께 씀, 정답 ③)으로 바꿈. 6-1은 정답을 ②로 옮겨 전체 분포 ①3 ②3 ③4.
- 메모 이름표 `pitch`를 「발표: 맡은 칸과 한마디」로(04 화면 문구와 맞춤). 설계표의 퀴즈 분포와 50분 흐름의 옛 표기(1분 대본)를 고침.
- 84~85쪽 예시 답안을 옮겨 적었던 줄을 지우고 「교과서 예시 답안이라 옮기지 않음」만 남김.
