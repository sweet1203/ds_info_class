**질문폼(info-u3-io) 근거** — 1번 ← 01 분류 게임·`myApp`, 2번 ← 02 직접 입력하고 실행하기(`ioRes`·`intWhy`), 3번 ← 03 파일 모드 실험실(`fileMis`·`modeWhy`). 셋 다 27분 무렵까지 끝남. 코랩 실습은 질문폼 근거로 쓰지 않음.

**50분 흐름** — 도입(3분) 도입 질문·처음 생각 → **01(3~9분)** 3단계 그림, 분류 6장, 내 앱 메모 → **02(9~17분)** print()·input() 예제 훑기, 직접 입력 실행 두 번(int 있음/없음), 메모(지식 키우기는 접어 둠) → **03(17~27분)** open() 그림·모드 표·함수 표 훑기, 파일 모드 실험실 미션 세 개, 메모 → **04(27~43분)** 코랩 열기·로그인·사본 저장(3~4분), 예제 따라 하기 → 정사각형 → 한 줄 평(두 번 실행) → 메모·개념 정리 → 마무리(43~50분). 응용하기(CSV)는 먼저 끝낸 학생용.

**코랩 노트북(`assets/io_files.ipynb`)** — 교과서코드 122~124쪽을 바탕으로 만듦. 출력은 비운 채 저장. 로컬 python3로 input()에 값을 넣어 모든 칸을 실행해 확인함(스스로 해결하기 빈칸은 시험할 때만 답을 넣어 실행).
- 123쪽 「연인의_곁.txt」 코드: **같은 구조(open 'w' → write 두 줄 → close / open 'r' → read → print → close)**로 두고, 파일 이름과 내용만 「나의_다짐.txt」와 새 문장으로 바꿈(시 원문과 데이터 파일을 저장소에 넣지 않음). 학생이 자기 다짐으로 바꿔 쓰게 안내. 'a' 모드와 readlines()를 확인하는 칸을 덧붙임.
- 124쪽 스스로 해결하기 1·2: 교과서처럼 빈칸 뼈대를 마크다운으로 보여 주고 실행 칸은 비움(정답 코드 없음). 2번은 파일 내용을 읽어 확인하는 칸을 따로 둠(두 번 실행해 'a' 모드 확인). 인코딩 옆 설명을 마크다운에.
- 124쪽 응용하기: 공공 데이터 CSV 파일을 쓰지 않고, 노트북 안에서 「사물함_위치.csv」(가상의 짧은 자료, 값 안에 쉼표 없음)를 만들어 같은 뼈대(with·readline()·readlines())로 읽게 함. 교과서는 euc-kr 파일이라 `encoding='euc-kr'`, 여기서는 직접 만든 utf-8 파일이라 `encoding='utf-8'`.

**줄인 것** — 122쪽 삽화, 124쪽 메모장 화면(예시 답안)과 응용하기 실행 결과는 넣지 않음. 지식 키우기(125쪽 함수란?)는 02 화면에 접어 두고 그림 대신 글로만(퀴즈·질문폼에서 묻지 않음). 124쪽 응용하기는 선택(더 해 보기)으로. 03 실험실은 r·w·a와 read()·readlines()만 다룸(readline()은 표와 노트북 응용하기에서). 개념 정리하기는 교과서 문장을 옮기지 않고 새 상황 문장 빈칸으로.

**확인할 점**
- 123쪽 표의 「readline(): 파일 포인터의 위치를 다음 줄로 이동한다」는 한 줄을 읽어 돌려준다는 점이 빠져 있음. 화면에는 「한 줄을 읽어 오고, 파일 포인터의 위치를 다음 줄로 이동해요」로 바로잡음.
- 122쪽 input() 예제 실행 결과 「몇 살이세요? 19」: 프롬프트 문자열 `'몇 살이세요?'` 끝에 공백이 없어 실제로는 「몇 살이세요?19」로 붙어서 보임. 화면 실행 결과는 실제대로 고침.
- 124쪽 응용하기 실행 결과에서 `"1호선 1`, `2번 출입구 사이 복도"`처럼 칸이 깨지는 것은 큰따옴표 안의 쉼표까지 split(',')으로 나눴기 때문(교과서 결과 그대로). 노트북에서는 값 안에 쉼표가 없는 자료를 써서 이 문제를 피함. 수업 중 질문이 나오면 설명 필요.
- 124쪽 응용하기 주석 「파일에 맨 앞줄인…」은 「파일의 맨 앞줄인…」이 자연스러워 노트북은 「파일의」로 씀.
- 02 체험의 오류 메시지(TypeError·ValueError)와 03 실험실의 FileNotFoundError 문장은 파이썬 3.14로 확인함.

**검토 반영(1차)**
- 마무리 퀴즈 5-1을 125쪽 개념 정리와 같은 문장(표준 입력과 표준 출력을 합쳐…)에서 사례형(input()과 print()만 쓰는 프로그램의 입출력은?)으로 바꿈. key3 첫 칸·셋째 칸과 03 callout·쉽게 말하면의 「파일 열기 → 파일 처리 → 파일 닫기의 3단계」 문장을 다른 구조로 고침.
- 퀴즈 4-2 보기를 출력 모양으로 통일(`AB`, `A B`, `A(줄 바꿈)B`). 퀴즈 5-2 보기를 글자 수 순서로 다시 놓음(정답 위치 그대로). 분포 ①4 ②5 ③4.
- 02 직접 입력하고 실행하기: 한글 입력 중(조합 중) Enter는 무시(`isComposing`·keyCode 229)해서 받침이 잘리거나 두 번 넘어가지 않게 함. 입력을 기다리는 동안 코드 바꾸기 버튼을 비활성하고 「입력이 끝나야 코드를 바꿀 수 있어요」 안내.
- 파일 모드 실험실: 'w'와 'a' 묶음을 오가도 학생이 고쳐 쓴 내용을 묶음마다 기억. 「폴더 비우기」를 누르면 미션 표시도 처음부터 다시(✔ 지움). 이미 해 본 미션은 「(이전에 해 봄)」으로 보이고, 기록(`fileMis`)은 지금까지 해 본 미션을 모두 남김.
- 노트북 응용하기 안내를 「split() 메소드는 142쪽 지식 키우기」로 고침(PDF 55쪽에서 확인: 142쪽 지식 키우기 「split() 메소드와 map() 함수」, for문은 137쪽).
- 화면 체험의 값 표시(pyRepr)를 파이썬과 똑같게 고침: 숫자 키는 따옴표 없이(`{0: [1, 3]}`), 딕셔너리 키는 넣은 순서대로(숫자 키도 `DK()`로 순서 유지), 작은따옴표가 든 문자열은 `"it's"`처럼 표시. 네 차시 lesson.js에 같은 코드로 넣고 python3 출력과 대조함.
