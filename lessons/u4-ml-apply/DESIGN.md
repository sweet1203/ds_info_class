## 왜 칼로리 소모량 예측을 중심 실습으로 골랐나 (추천안)
- **준비 시간이 가장 짧다**: 추가 기능 설치가 필요 없고(은하는 Image Analytics, 선박은 Geo 설치 필요), 인터넷도 필요 없다(이미지 임베딩은 서버로 이미지를 보내 계산해 시간이 걸림).
- **이어지는 실습이다**: Ⅱ단원에서 같은 데이터를 합치고(Merge Data) 시각화했으므로 저장한 워크플로에 위젯 4개만 붙이면 된다. 저장 파일이 없어도 교과서 워크플로(선생님 폴더)를 열고 File 위젯 두 개의 파일만 다시 고르면 3분 안에 준비된다.
- **프로젝트 과정 ③ 학습 · ④ 평가를 온전히 겪는다**: 독립 변수 · 종속변수 역할 정하기 → 훈련/테스트 나누기 → 학습 → 테스트 데이터로 평가 지표 읽기까지 한 흐름. 평가 지표(R2 · MAE)가 숫자로 바로 나와 질문폼 3번의 근거가 분명하다.
- 분류(은하) · 군집(선박)은 04에서 「예측값의 형태로 유형 고르기」 분류 게임과 카드로 개념만 다루고, 실습은 시간이 남는 학생이나 다음 시간에 하도록 접었다.

## 50분 흐름 (시작 화면 「50분 계획」과 같음)
시작(2분) 오렌지3 실행, 파일 확인 → 01(6분, ~8분) 카드 훑기, 분류 게임 6장, `solveWhy` → 02(7분, ~15분) SDGs 사례 · 프로젝트 과정 · 세 문제 표 훑기(모둠원 역할은 뺌), 목표 칩 · 아이디어 메모(발표는 선생님 운영) → **03(15분, ~30분)** 평가 지표 미리 보기 3분(오렌지3가 늦게 열려도 이 동안 준비됨) → 워크플로 열기 3분 → Select Columns · Data Sampler · Linear Regression · Predictions 연결 6분 → 내 결과 메모 3분(`calRes` · `calRead`가 28~30분에 닿음) → 04(10분, ~40분) 유형 분류 게임 · 퀴즈(선택 실습은 남는 시간에) → 마무리(10분) 핵심 질문, 퀴즈, 질문폼.

## 줄인 것
- 189쪽 함께 해결하기의 「조사하여 발표」는 목표 칩 + 아이디어 메모로 줄이고, 발표는 선생님 운영에 맡김.
- 190쪽 모둠원 역할 5개는 50분 안에 들지 않아 이 차시 화면에서 뺌(u4-review 시작 화면의 역할 메모 힌트로 씀).
- 193쪽 스스로 해결하기(온라인 설문지 → File 위젯에 주소 → Predictions)는 설문지 만들기와 공유에 시간이 들어 03에 접어 두고 「선생님 안내가 있을 때」로 둠. 주소는 화면에 쓰지 않음.
- 194~195쪽 은하 분류, 196~197쪽 불법 조업 의심 선박 군집화는 04에 단계 안내를 접어 두고(위젯 이름 · 연결 순서는 교과서 워크플로 파일에서 확인), 펼친 화면에는 유형만 적은 카드 두 장만 둠. 195쪽 스스로 해결하기(나만의 은하 이미지 분류)는 넣지 않음.
- 197쪽 개념 정리하기, 198쪽 맞춤 활동, 199쪽 보충 활동은 교과서 문항이라 옮기지 않음. 같은 개념을 01 · 04의 새 상황 분류 게임(빵 판매량, 주사위, 잎 사진, 택배 상자, 자전거 대여, 가로등 신고 등)과 퀴즈로 다룸.

## 노트북 `assets/kmeans_steps.ipynb` (선택 · 심화)
교과서 노트북(199쪽 QR)은 1~4단계가 모두 완성된 코드라, 심화 활동 「소스 코드를 완성하면서」에 맞게 고쳤다.
- 1 라이브러리 불러오기(교과서와 같음) · 2 데이터 생성(교과서와 같은 `make_blobs(n_samples=20, random_state=4)` + 레이블 없이 점 그려 보기)은 **따라 하기**.
- 2-1 **따라 하기 예제**를 새로 넣음: 반복 횟수 제한 없이 k-평균을 한 번 끝까지 실행해 `labels_` · `cluster_centers_`를 보고 그리기(원 · 사각형).
- 3 학습 및 시각화 함수 · 4 2×2 시각화는 **스스로 해결하기 빈 셀 + 접힌 힌트**. 힌트는 「최대 반복 횟수를 정하는 인자는 max_iter」처럼 인자 · 함수 이름과 하는 일만 말로 알려 주고, 완성된 코드 줄은 넣지 않음(1차 검토 반영).
- 5 더 해 보기(군집 3개, 데이터 바꾸기) 빈 셀.
- 출력은 비운 채 저장. 로컬 python3(scikit-learn 1.9)로 따라 하기 셀을 모두 실행해 오류가 없음을 확인했고, 저장소 밖 시험용 답으로 3 · 4가 힌트대로 동작해 반복할수록 sum of distance가 줄어드는 것을 확인함.

## 확인할 점
- 193쪽 「결정계수는 독립 변수와 종속변수의 상관관계로, 1에 가까울수록 성능이 우수」 — 결정계수는 모델이 종속변수의 변화를 얼마나 설명하는지를 나타내는 값이라 「상관관계」라는 설명은 엄밀하지 않음. 화면에는 「회귀 모델의 정확도를 나타내는 지표, 1에 가까울수록 성능이 우수」까지만 씀.
- 193쪽 R2를 「96.7%」, 195쪽 CA를 「97%」와 「96.7%」로 함께 씀(같은 쪽 안에서 표기가 다름). 화면에는 교과서 수치를 옮기지 않고 학생이 자기 결과를 적게 함. 로컬에서 같은 데이터로 8:2 무작위 분할을 여러 번 해 보니 교과서 값과 비슷하게 나옴(계산이 맞음을 확인).
- 193쪽 「Remainning Data」, 194쪽 그림 「Remaining Adta」, 195쪽 「Display Wigets on Top」, 196 · 197쪽 「불업 조업」은 오타. 화면에는 Remaining Data, Display Widgets on Top, 불법 조업으로 씀.
- 192쪽 교과서 그림과 워크플로 파일에서는 **Gender도 Features**에 넣음. Ⅱ단원(74쪽, u2-preprocess)에서는 Gender를 meta로 바꿔 두었으므로, 저장 파일을 쓰면 Gender가 Metas에 있을 수 있음 → 설정 표에 「Metas에 있으면 Features로 옮기기」를 적음.
- 교과서 워크플로(192쪽)의 Merge Data는 User_ID가 아니라 **Row index**로 맞춰져 있음. 두 파일의 줄 순서가 같아 결과는 같지만(확인함), Ⅱ단원 화면은 User_ID로 맞추라고 안내했음.
- 194쪽 ➊ 「Data Sampler에 Predictions 위젯을 연결」은 연결선을 Remaining Data로 바꿔야 함(그림에는 나옴). 화면 접힌 안내에 적음.
- 199쪽 노트북 그림 제목 「sum of distance」는 `-model.score(X)`, 곧 거리 **제곱**의 합이라 노트북 힌트에 「거리의 제곱을 모두 더한 값」으로 씀.
- 01 「해결할 수 없는 문제」: 과정안은 「기계학습을 적용할 필요가 없는 문제」도 구분하라고 하지만 교과서 본문에는 없어 다루지 않음.
- 03 「평가 지표 미리 보기」의 6명 데이터와 모델 A · B 예측값은 새로 만든 수치. MAE · R2를 손으로 검산함(모델 B는 R2가 음수가 되지 않게 골라 0과 1 사이에 둠). 모델 B는 실제 실습 결과와 헷갈리지 않게 「속성을 일부만 쓴 모델」로만 설명함.
