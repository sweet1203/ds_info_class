01

수행 시간과 기억 공간

교과서 99쪽 · 알고리즘 설계와 성능 평가, 수행 시간, 기억 공간, 연산 횟수

쉽게 말하면같은 답을 내는 알고리즘이라도 계산을 몇 번 하는지(수행 시간)와 메모리를 얼마나 쓰는지(기억 공간)가 다를 수 있어요. 데이터가 커질 때 이 둘이 어떻게 변하는지 비교해 더 효율적인 알고리즘을 골라요.

⚖️ 알고리즘의 성능 평가

같은 문제라도 적용할 수 있는 알고리즘이 다양하기 때문에 그중 효율적인 알고리즘을 선택해야 해요. 컴퓨팅 시스템으로 문제를 해결할 때 무한정 시간을 들이거나 너무 많은 기억 공간이 필요하다면 비효율적이기 때문이에요. 일반적으로 데이터의 크기가 커짐에 따라 수행 시간과 기억 공간 측면에서 성능이 어떻게 변하는지 비교해 알고리즘의 성능을 평가해요.

⏱️

수행 시간

어떤 알고리즘을 수행하는 데 얼마나 오랜 시간이 걸리는지 분석한 것이에요. 필요한 사칙연산 횟수가 많아지면 알고리즘 전체를 수행하는 시간이 늘어나므로, 연산 횟수가 수행 시간에 해당해요.

💾

기억 공간

어떤 알고리즘을 수행하는 데 얼마나 많은 공간(메모리/기억 장소)이 필요한지 분석한 것이에요.

🧮 예제 · 1부터 n까지의 합을 구하는 두 알고리즘

알고리즘 1 · 하나씩 더하기

  1. 합(s) = 0, 숫자(n) = 1
  2. s = s + n
  3. n은 1씩 증가
  4. n이 끝 수보다 작거나 같을 때 ❷와 ❸ 과정 반복

숫자 2개에 대해서만 더하기(+) 연산을 할 수 있는 컴퓨팅 시스템의 한계 때문에, 앞 단계의 결과에 다음 숫자를 더하는 과정을 반복해요. 이 기능을 모델링해 s = s + n과 같은 식을 만들어요.

알고리즘 2 · 짝지어 계산하기

  1. 합(s) = 0, 숫자(n) = 끝 수
  2. s = n × (n + 1) / 2

1부터 n까지의 숫자에 반대 순서로 한 번 더 나열한 숫자를 짝지어 더하면 (1 + n), (2 + n − 1) …처럼 모두 같은 값이 돼요. 이런 작은 문제로 나누는 과정을 모델링해 s = n × (n + 1) / 2와 같은 식을 만들어요. 곱셈 한 번, 덧셈 한 번, 나눗셈 한 번이에요.

n을 바꾸며 알고리즘 2의 짝짓기를 살펴봐요.

6

🏁 체험 · 두 알고리즘의 연산 횟수 비교하기

끝 수 n을 정하고 실행을 눌러요. 알고리즘 1은 덧셈을 한 번 할 때마다 연산 횟수가 1씩 늘어요. 알고리즘 2는 덧셈·곱셈·나눗셈을 세어요. n을 3가지 이상 바꿔 보며 결과를 기록해요.

02

O 표기법(빅오 표기법)

교과서 100쪽 · 정비례 그래프와 상수 그래프, O(n)과 O(1), 지식 키우기

쉽게 말하면입력 크기 n이 커질 때 연산 횟수가 어떻게 늘어나는지를 짧게 적는 방법이에요. n에 정비례해 늘면 O(n), n과 관계없이 일정하면 O(1)이라고 써요.

📈 내 기록으로 그린 연산 횟수 그래프

01에서 기록한 n과 연산 횟수가 점으로 찍혀요. 알고리즘 1은 정비례 그래프, 알고리즘 2는 상수 그래프가 돼요.

알고리즘 1 · O(n)

입력 크기 n에 대해 덧셈을 n번 수행해요. 이처럼 문제 해결에 필요한 연산 횟수가 입력 크기에 「정비례」할 때 수행 시간은 O(n)으로 표현해요.

알고리즘 2 · O(1)

입력 크기 n과 관계없이 3번의 연산을 수행해요. 이처럼 입력 크기와 관계없이 연산 횟수가 일정한 경우는 O(1)로 표현해요.

이처럼 같은 문제를 해결하는 두 알고리즘의 수행 시간을 비교(O(n) > O(1))한 뒤, 더 효율적인 알고리즘 2를 선택해요. 수행 시간을 표현하는 방법은 여러 가지가 있는데, 그중 O 표기법(빅오 표기법)을 가장 많이 사용해요.

🔭 지식 키우기 · 여러 가지 O 표기법 (100쪽 심화)

  • O(1) 입력 크기 n과 수행 시간이 무관할 때
  • O(n) 입력 크기 n에 비례하여 수행 시간이 증가할 때
  • O(n²) 입력 크기 n의 제곱에 비례하여 수행 시간이 증가할 때
  • O(2ⁿ) 입력 크기가 n일 때 2의 n 제곱 값에 비례하여 수행 시간이 증가할 때

n을 바꿔 네 가지 연산 횟수를 비교해요. 막대는 가장 큰 값을 기준으로 그려요.

5

그래프에서 기울기가 완만할수록 수행 시간이 작고, 기울기가 급할수록 수행 시간이 커요. 따라서 수행 시간이 일정한 O(1)인 알고리즘이 가장 효율적이에요. 정렬 알고리즘과 탐색 알고리즘에서 다시 만나요.

🎯 어떤 O 표기법일까?

상황 6개를 읽고, n이 커질 때 연산 횟수가 어떻게 늘어나는지 생각해 골라요.

03

함께 해결하기 · 하노이 탑 문제

교과서 101쪽 · 분석 · 실습, 문제 분해 → 모델링 → 성능 분석

쉽게 말하면원반 1개, 2개, 3개처럼 작은 문제부터 직접 옮겨 보고, 원반이 하나 늘 때 앞의 작은 문제를 어떻게 다시 쓰는지 찾아요. 그다음 원반 수에 따라 이동 횟수가 어떻게 늘어나는지 분석해요.

🗼 하노이 탑 옮기기

조건
  1. 크기가 다른 원반 n개를 출발점 기둥(A)에서 도착점 기둥(C)으로 전부 옮긴다.
  2. 원반은 한 번에 1개씩만 옮길 수 있다.
  3. 원반은 한 기둥의 맨 위 원반에서 뽑아 다른 기둥의 맨 위로만 옮길 수 있다.
  4. 원반을 옮기는 과정에서 큰 원반을 작은 원반 위로 올릴 수 없다.
  5. 중간의 보조 기둥(B)을 이용할 수 있다.

옮기는 방법 원반을 뺄 기둥을 누르고, 놓을 기둥을 눌러요. 모두 C로 옮기면 이동 횟수가 자동으로 기록돼요.

🧩 문제 분해 · 작은 문제부터 해결하기

  1. 1-1. 원반이 1개일 때 몇 번 이동해야 하는지 해결해 봐요.
  2. 1-2. 원반이 2개일 때 몇 번 이동해야 하는지 해결해 봐요. 처음 한 번 옮긴 뒤의 현재 상태에서 위의 원반은 어디에 있나요?
  3. 1-3. 같은 해결 방법으로 원반이 3개일 때 몇 번 이동해야 하는지 문제 상태를 확인하며 해결해 봐요. 맨 아래 큰 원반을 C로 옮기기 바로 전에, 나머지 원반들은 어디에 모여 있어야 할까요?

📐 모델링 · n개일 때와 n−1개일 때의 관계

원반의 개수가 n일 때와 n−1일 때 해결 방법의 관계를 살펴보고, 괄호에 알맞은 기둥(A, B, C)을 적어요. 1번이 가장 작은 원반, n번이 가장 큰 원반이에요. 정답은 화면에 나오지 않아요. 직접 옮겨 본 순서로 짝과 확인해요.

n이 1인 경우: 1번 원반을 현재 위치에서 ( )로 이동
n이 1이 아닌 경우: n−1번까지의 원반을 ( )로 이동
n번 원반을 ( )로 이동
n−1번까지의 원반을 ( )에서 ( )로 이동

📊 성능 분석 · 원반 수에 따른 이동 횟수

단위 연산 횟수는 원반의 위치 이동 횟수예요. 위에서 옮긴 내 기록이 표에 들어가요(가장 적게 옮긴 기록). 원반 수를 바꿔 가며 표를 채워요.

04

마무리

핵심 문장 · 처음 생각과 비교 · 마무리 퀴즈 · 질문폼

같은 문제라도 적용할 수 있는 알고리즘은 다양하므로 효율적인 알고리즘을 선택해야 한다. 알고리즘의 효율성은 수행 시간과 기억 공간 측면에서 살펴보며, 연산 횟수가 수행 시간에 해당한다.
수행 시간은 주로 O 표기법(빅오 표기법)으로 나타낸다. 연산 횟수가 입력 크기에 정비례하면 O(n), 입력 크기와 관계없이 일정하면 O(1)이며, O(n²), O(2ⁿ)처럼 더 빠르게 늘어나는 경우도 있다.
하노이 탑은 원반 n개 문제를 원반 n−1개 문제로 나누어(문제 분해) 해결 방법의 관계를 모델링할 수 있고, 원반 수가 늘수록 이동 횟수가 매우 빠르게 늘어난다.
